# Proposal: Remove Dead Standard More UI

## Intent
Since commit `b00c794ab` ("feat(aurora): enable Aurora UI for all themes and complete MoreScreen", 2026-01-12), `AppTheme.isAuroraStyle` defaults to `true` and no entry in the `AppTheme` enum overrides it to `false`. Every code path guarded by `if (theme.isAuroraStyle) { ... } else { ... }` therefore always takes the Aurora branch — the "else" branches, including the entire standard (non-Aurora) `MoreScreen` composable, are unreachable in any shipped build. This change removes that dead code so the codebase reflects what actually ships, and so the follow-up reorganization of the More section (`reorganize-more-section-ia`) only has one live UI to redesign instead of two.

## Scope
- Delete `app/src/main/java/eu/kanade/presentation/more/MoreScreen.kt` (the standard More screen composable) and its tests under `androidTest`/`test`
- In `app/src/main/java/eu/kanade/tachiyomi/ui/more/MoreTab.kt`: remove the `if (theme.isAuroraStyle) { MoreScreenAurora(...) } else { MoreScreen(...) }` branch, leaving a direct call to `MoreScreenAurora`; remove parameters/callbacks only the standard variant used (e.g. the vestigial `onClickStorage` parameter at `MoreScreen.kt:52`, never wired to a visible UI item)
- Collapse the same `if (theme.isAuroraStyle) { ... } else { ... }` pattern in the ~15 other locations that branch on it: the three history screens (`MangaHistoryScreen.kt`, `NovelHistoryScreen.kt`, `AnimeHistoryScreen.kt`), `HistoryDialogs.kt`, `MangaScreen.kt`, `AnimeScreen.kt`, `NovelScreen.kt`, `CategoryListItem.kt`, `CategoryFloatingActionButton.kt`, `MangaCategoryScreen.kt`, `AnimeCategoryScreen.kt`, `DownloadEngineCard.kt`, `DownloadQueueItem.kt`, `CategoriesTab.kt`, `HomeScreen.kt` (two sites), `StatsTab.kt` plus the three media-specific stats tabs, `UpdatesTab.kt`, `HistoriesTab.kt`, `AnimeLibraryTab.kt`, `MainActivity.kt`, `DownloadsTab.kt`, the three `*DownloadQueueScreen.kt` files, and `ReaderViewModel.kt` — each collapses to its Aurora branch
- **Not in scope**: removing `isAuroraStyle` from the `AppTheme` enum, or `LocalIsAuroraTheme`/`theme.isAuroraStyle` as a concept. Other genuinely-independent Aurora-vs-Classic toggles (home hero CTA mode, recent-card mode, title-card CTA mode — see `theming-aurora-ui` spec) keep using `isAuroraStyle`-adjacent machinery for their own purposes; only the specific "which More-screen composable to render" branch, and its structurally identical siblings, are dead
- **Not in scope**: any change to the content or structure of `MoreScreenAurora.kt` itself — that's `reorganize-more-section-ia`

## Approach
Mechanical, file-by-file removal: for each of the ~16 sites, confirm the `false`/`else` branch is genuinely unreachable (no `AppTheme` entry produces it), collapse to the single live branch, and compile after each file to catch broken references before moving to the next. Finish with a full build and a manual pass through the More tab and the other affected screens (History, Category, Stats, Downloads, Library) to confirm nothing visibly changes — this change is expected to be invisible to end users.
